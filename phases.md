# Phase Roadmap — denisakp.me Post-Nuxt-UI Migration

**Status**: 001 (Nuxt 4 + Nuxt UI migration) feature-complete on branch
`001-nuxt4-ui-upgrade`. 8 human-only verification tasks pending
(browser walks + Lighthouse). All subsequent phases listed below assume
001 has been merged to `main`.

Each phase is a **separate spec-kit branch + spec + plan + tasks**.
Reviewable independently. Ship in order or skip optional phases.

---

## Phase 002 — Content Surfaces

**Branch**: `002-content-surfaces`
**Goal**: Surface existing identity + content. Lay the metadata
foundation later phases depend on.
**Estimated effort**: ~4 hours.

### Scope

1. **`/about` page** — long-form bio, photo, social links, expanded
   beyond the inline blurb on `/`. SEO landing page for the author
   name. Pulls from `data/projects.ts` for "currently working on".
2. **`/talks` page** — render `data/talks.ts` (exists, currently
   orphan). Each talk: title, conference/venue, date, slides link,
   recording link.
3. **Latest 3 posts on homepage** — query `queryCollection("content")
   .order("date", "DESC").limit(3).all()` server-side, render below
   the existing About/Skills/Contact grid.
4. **Article publication date + reading time** in `/blog/<slug>`
   header. `date` is already in frontmatter; compute reading-time
   from `article.body` (`Math.ceil(wordCount / 200)`). Display as
   `2026-05-27 · 7 min read` below the title.
5. **Custom `error.vue`** at repo root — brand-styled 404 + 500 with
   "Go home" + "Latest posts" links.

### Dependencies

None. Only depends on 001 being merged.

### Why first

- Foundation for 003 (related posts needs `date` visible; OG image
  needs `date`).
- Highest "looks more professional" signal per hour invested.
- All-additive: zero touch to existing components, just new files.

### Out of scope (deferred to later phases)

- Newsletter signup → 005.
- Per-post OG image generation → 003.
- Related posts → 003.

## Phase 003 — Social & Discovery

**Branch**: `003-social-discovery`
**Goal**: Make individual posts share well, surface adjacent reads,
let subscribers follow without a website visit.
**Estimated effort**: ~4 hours.

### Scope

1. **Per-post OG image** via `@nuxtjs/og-image` (free tier supports
   build-time SVG generation). Each post gets an image with title +
   date + author byline rendered at build, cached in
   `.output/public/__og-image__/`. Replaces the single Cloudinary
   fallback used by every post today.
2. **RSS feed at `/rss.xml`** — generated by a Nitro server route
   that runs `queryCollection("content").order("date", "DESC").all()`
   and emits RFC 4287 / RSS 2.0 XML. Link tag in `app.vue` `<head>`.
3. **Related posts** — after article body, before Giscus. Compute 3
   posts sharing the most `tags` + `topics` with the current article.
   Render as a `<UCard>` row reusing `components/Post.vue`.

### Dependencies

- 002 must land first (article date + reading time exist; OG template
  references date).

### Why second

- Compounding effect: posts written before 003 also gain OG images
  retroactively (build-time generation).
- Network effect for RSS — reader can subscribe once, gets every
  future post.
- Related posts increases pages-per-session.

## Phase 004 — Full-text Search

**Branch**: `004-search-v2`
**Goal**: Replace title-only search (`/api/search`) with full-text
indexed search across post bodies.
**Estimated effort**: ~3 hours.

### Scope

1. **Integrate Pagefind** — client-side WASM full-text search over
   prerendered HTML. Zero server cost, zero ongoing infra.
2. **Build hook** — postbuild script runs `pagefind --site
   .output/public` to generate `_pagefind/` index.
3. **Header search modal rewrite** — replace `$fetch("/api/search")`
   with Pagefind's `PagefindUI` component or DIY `pagefind.search()`
   API for custom rendering.
4. **Remove `server/api/search.get.ts`** — no longer needed.

### Dependencies

- Independent of 002/003 in principle, but 003's related-posts UI
  pattern can be reused for search results.

### Why third

- Search is rarely the top-traffic feature on a small blog (most
  visitors land via Google or RSS) → ship after the surfaces that
  matter more first.
- Pagefind adds ~30 KB JS + ~50 KB index per 100 posts. Worth
  measuring against the NFR-003 ceiling (1500 KB gzip).

## Phase 005 — Engagement

**Branch**: `005-engagement`
**Goal**: Direct reader retention surfaces beyond the post itself.
**Estimated effort**: ~3 hours.

### Scope

1. **Newsletter signup** — Buttondown or Bento embed in `/about`
   footer + below blog post body. Minimal config: single email
   input, double-opt-in handled by provider.
2. **`/uses` page** — engineer-blog microformat. Sections: editor +
   shell, hardware, dotfiles repo link, cloud + observability stack,
   AI tooling.
3. **`/now` page** — current focus / projects / books. Update
   monthly. Cheap differentiator vs static `/about`.
4. **Mobile TOC drawer** — sticky TOC is `lg:` only. Add `<details>`
   collapsible TOC at top of article body for mobile (< lg) so phone
   readers can also navigate.

### Dependencies

None hard. Independent of 002–004.

### Why fourth

- Diminishing returns vs 002/003 — these are nice-to-haves for the
  existing audience, not new-visitor surfaces.
- Mobile TOC matters most after analytics show > 30 % mobile
  readership (verify post-002).

## Phase 006 — Privacy & i18n *(optional)*

**Branch**: `006-privacy-i18n`
**Goal**: Swap analytics to a privacy-respecting tool + add
French/English bilingual support.
**Estimated effort**: ~1 day (mostly content translation).

### Scope

1. **Analytics swap** — replace Google Tag Manager script in
   `app.vue` with Plausible or Umami. Smaller bundle, no
   cookie-banner trigger, GDPR-clean.
2. **`@nuxtjs/i18n` integration** — locale codes `en` (default) +
   `fr`. Routing: `/blog` (EN) + `/fr/blog` (FR), or domain prefix.
3. **Frontmatter `lang` field** — add to `content.config.ts` Zod
   schema. Posts can be EN-only, FR-only, or have both.
4. **Translate UI strings** — Header nav, Footer, button labels,
   404 page.

### Dependencies

Depends on 005 being merged (newsletter copy needs translating too).

### Why optional

- Heavy lift. Translating existing 12+ posts is ~1 day per post for
  quality work.
- Most denisakp.me readers (per stack assumption) are likely already
  comfortable reading technical English.
- Only worth doing if there's a measurable FR-speaking audience
  signal (e.g., analytics shows > 30 % `Accept-Language: fr`).

## Phase 007 — PWA & Accessibility Polish *(optional)*

**Branch**: `007-pwa-a11y`
**Goal**: Installability + accessibility hardening.
**Estimated effort**: ~half day.

### Scope

1. **PWA via `@vite-pwa/nuxt`** — manifest already partially set
   up in `app.vue`. Service worker for offline reading of cached
   posts.
2. **Skip-to-content link** — first focusable element on every page,
   visible only when focused.
3. **Print stylesheet** — `@media print` rules for blog post pages:
   hide Header / Footer / TOC / Giscus / PrevNext / code-copy
   buttons; respect `prefers-color-scheme` default.
4. **Tag pages `/tags/<tag>`** — tags are already in frontmatter
   but currently un-routable. Mirror the `/topics/<slug>` page
   pattern with `queryCollection().where("tags", "LIKE", ...)`.

### Dependencies

None hard.

### Why optional / last

- PWA install rate on small blogs is ~< 1 %. Engineering effort vs
  reader value is unfavorable.
- Tag pages are nice-to-have but Topics already provide categorical
  navigation. Add only if posts grow beyond ~30 and tag/topic
  distinction becomes meaningful.

## Cross-phase concerns

### Constitution

All phases must satisfy v1.0.0 principles I–V (TS+Zod, NuxtImg-only,
a11y+dark, component grouping, content+performance). Each spec MUST
include the same `## Constitution Check` gate as 001.

### NFR-003 bundle ceiling

Current branch: **1176 KB gzip** / **1500 KB ceiling** = 78 % used.
Each phase MUST recheck bundle size in its Polish phase and reject if
new ceiling exceeded. Pagefind (004) is the largest bundle risk —
budget ~80 KB gzip for it.

### Spec Kit workflow

For each phase:

1. `/speckit-specify "<phase title>"` from `main` HEAD.
2. `/speckit-clarify` — resolve open questions.
3. `/speckit-plan`.
4. `/speckit-tasks`.
5. `/speckit-analyze` — fix issues if any.
6. `/speckit-implement` — phase-by-phase execution.
7. Commit. Open PR. Merge after human verification of any
   human-only tasks.

### Sequencing recommendation

**Default**: 002 → 003 → 004 → 005, defer 006 + 007 unless explicit
signal.

**MVP path**: 002 only. Ship it. Re-evaluate after a month of
traffic.
